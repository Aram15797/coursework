5 
 
Ներածություն 
Ժամանակակից առողջապահական համակարգերում տեղեկատվական 
տեխնոլոգիաների կիրառումը դարձել է բժշկական ծառայությունների 
կազմակերպման, տվյալների պահպանման և մշակման գործընթացների 
անբաժանելի բաղադրիչ։ Բուժհաստատություններում ամեն օր ստեղծվում և 
մշակվում է մեծ ծավալի տեղեկատվություն, որը ներառում է հիվանդների անձնական 
տվյալները, բժշկական պատմությունները, ախտորոշումները, լաբորատոր և 
գործիքային հետազոտությունների արդյունքները, ինչպես նաև նշանակված 
բուժումների վերաբերյալ տվյալները։ Այս տեղեկատվության արդյունավետ 
կառավարումը պահանջում է հուսալի և անվտանգ տվյալների հենքի առկայություն, 
որը կապահովի տվյալների ամբողջականությունը, արագ հասանելիությունը և 
ճշգրտությունը։  
Տվյալների հենքերի կառավարման համար լայնորեն կիրառվում է SQL (Structured 
Query Language) լեզուն, որը նախատեսված է տվյալների ստեղծման, պահպանման, 
փոփոխման և մշակման համար։ SQL-ը հանդիսանում է հարաբերական տվյալների 
բազաների հետ աշխատանքի հիմնական ստանդարտ գործիքներից մեկը և 
հնարավորություն է տալիս իրականացնել տվյալների արդյունավետ որոնում, 
վերլուծություն և կառավարում։ Այս աշխատանքում տվյալների բազայի 
կառավարման համար օգտագործվել է PostgreSQL համակարգը, որը SQL լեզվի վրա 
հիմնված, բաց կոդով և բարձր հուսալիությամբ օժտված տվյալների բազայի 
կառավարման միջավայր է։ PostgreSQL-ը առանձնանում է տվյալների 
ամբողջականության պահպանման բարձր մակարդակով, մեծածավալ տվյալների 
արդյունավետ մշակման հնարավորություններով և լայն կիրառությամբ տարբեր 
տեղեկատվական համակարգերում, այդ թվում՝ առողջապահական ոլորտում։ 
Սույն կուրսային աշխատանքի նպատակն է նախագծել բուժհաստատության 
բժիշկների պորտալի տվյալների հենքը՝ ապահովելով հիվանդների տվյալների 
անվտանգ պահպանումը, ինչպես նաև բժշկական այցելությունների, 
ախտորոշումների և դեղորայքային նշանակումների արդյունավետ կառավարումը։ 
Աշխատանքի շրջանակներում իրականացվել է տվյալների հենքի կառուցվածքի 
նախագծում, սահմանվել են աղյուսակները, հիմնական և արտաքին բանալիները՝ 
ապահովելով տվյալների ամբողջականության պահպանման պահանջները։  
Արդյունքում մշակվել է բուժհաստատության բժիշկների պորտալի տվյալների հենքի 
ամբողջական նախագիծ, որը կարող է հիմք ծառայել բժշկական տեղեկատվական 
համակարգի ներդրման համար և նպաստել բուժհաստատության գործունեության 
ավտոմատացմանը, արդյունավետության բարձրացմանը և տվյալների կառավարման 
որակի բարելավմանը։

Մարդն իր գործունեության ընթացքում սովորել է ոչ միայն ինֆորմացիա 
հավաքել, այլև այն համակարգել: Որպեսզի կուտակված ինֆորմացիան մատչելի 
լինի, այն նախ հատուկ ձևով տեսակավորվել է, ապա համակարգվել 
տեղեկագրերում: Նման տեղեկագրեր են, օրինակ, կյանքի ամենաբազմազան 
ոլորտներին վերաբերող հանրագիտարանները: Որպեսզի նման գրականության 
միջոցով տեղեկություններ ստանաք, ասենք, որևէ եզակի բույսի վերաբերյալ, 
հավանաբար պետք է մասնագիտացված գրադարան գտնել, և հազարավոր գրքերից 
փնտրել պետք եղած ինֆորմացիան: Իսկ եթե նման գրադարան քաղաքում չկա, կամ 
էլ` համապատասխան ինֆորմացիան անհրաժեշտ է շտապ ձեռք բերել, ապա,

Ի՞նչ է PostgreSQL-ը։ 
PostgreSQL-ը, որը հայտնի է նաև որպես Postgres, բաց կոդով հարաբերական 
տվյալների բազայի կառավարման համակարգ է, որը առանձնանում է իր բարձր 
հուսալիությամբ, ճկունությամբ և բաց տեխնիկական ստանդարտների 
աջակցությամբ։ Այն համարվում է SQL ստանդարտին համապատասխանող և 
առավել կայուն ու հասուն տվյալների բազաներից մեկը, որը լայնորեն կիրառվում է 
ժամանակակից տեղեկատվական համակարգերում։ Այն հնարավորություն է տալիս 
արդյունավետ կերպով աշխատել ինչպես պարզ, այնպես էլ բարդ կառուցվածք 
ունեցող հարցումների հետ՝ ապահովելով տվյալների արագ և անվտանգ մշակում։      
Բացի հիմնական հարաբերական մոդելից, PostgreSQL-ը աջակցում է նաև ոչ 
հարաբերական տվյալների տեսակների, օրինակ՝ JSON և JSONB, ինչը այն դարձնում է 
առավել ճկուն և հարմար տարբեր տեսակի կիրառությունների համար։  
PostgreSQL-ի առանձնահատկությունները ներառում են հետևյալը.

Ինչպե՞ս է օգտագործվում PostgreSQL-ը։ 
PostgreSQL-ը «միասնական լուծում է» բազմաթիվ ձեռնարկությունների համար, 
որոնք փնտրում են իրենց տվյալների բազայի կառավարման համակարգերը (DBMS) 
բարելավելու ծախսարդյունավետ և արդյունավետ եղանակներ: Այն ընդարձակվող է 
և բավականաչափ բազմակողմանի՝ արագորեն աջակցելու տարբեր 
մասնագիտացված օգտագործման դեպքերի՝ հզոր ընդլայնման էկոհամակարգով, որը 
ներառում է ժամանակային շարքերի տվյալների տեսակների և աշխարհագրական 
վերլուծությունների նման ջանքեր: Կառուցված որպես բաց կոդով տվյալների բազայի 
լուծում, PostgreSQL-ը լիովին ազատ է լիցենզավորման սահմանափակումներից, 
մատակարարի կողմից կապվածության ներուժից կամ գերտեղակայման ռիսկից: 
PostgreSQL-ը կառավարվում է օբյեկտ-ռելացիոն տվյալների բազայի կառավարման 
համակարգի (ORDBMS) միջոցով:

Սրանք PostgreSQL-ի հիմնական առավելություններից մի քանիսն են՝ 
 
Կատարողականություն և մասշտաբայնություն, ներառյալ 
աշխարհատարածական աջակցությունը և անսահմանափակ 
համաժամանակությունը, և տվյալների խորը, ընդարձակ վերլուծությունը 
տվյալների բազմաթիվ տեսակների միջև:



«պատուհանի» (window) սահմաններում՝ առանց արդյունքային տողերի քանակը 
նվազեցնելու կամ տվյալների համախմբում իրականացնելու։                                                  
Ի տարբերություն ագրեգատ ֆունկցիաների, window functions-ը հաշվարկները 
կատարում են յուրաքանչյուր տողի մակարդակում՝ պահպանելով տվյալների 
սկզբնական կառուցվածքը և միաժամանակ ապահովելով լրացուցիչ վերլուծական 
արժեքներ։                                                                                                                                  
Դրանք կիրառվում են OVER() կառուցվածքի միջոցով, որը կարող է ներառել PARTITION 
BY (խմբավորում) և ORDER BY (դասավորում) բաղադրիչները, ինչպես նաև 
անհրաժեշտության դեպքում՝ frame clause։                                                                         
Window functions-ը լայնորեն կիրառվում են դասակարգման, կուտակային 
հաշվարկների և ժամանակային վերլուծությունների իրականացման համար՝

տվյալների որոնման և համապատասխանեցման մեխանիզմ են, որոնք հիմնված են 
նախապես սահմանված նմուշների վրա։ Դրանք հնարավորություն են տալիս

PostgreSQL-ում կանոնավոր արտահայտությունները լայնորեն կիրառվում են 
տեքստային դաշտերում համապատասխան արժեքների որոնման և կառուցվածքային 
ստուգման համար՝ ապահովելով բարձր ճշգրտություն և ճկունություն։ 
Կանոնավոր արտահայտությունները հատկապես օգտակար են այն դեպքերում, երբ 
անհրաժեշտ է գտնել որոշակի ձևաչափ ունեցող տվյալներ, իրականացնել մուտքային 
տվյալների վավերացում կամ ստուգել տվյալների համապատասխանությունը 
սահմանված կանոններին։ 
Շարահյուսություն՝

FROM table_name 
WHERE column_name ~ 'pattern'; 
~ օպերատորը օգտագործվում է տվյալ սյունակի արժեքը տվյալ կանոնավոր 
արտահայտության հետ համեմատելու համար և վերադարձնում է այն տողերը, 
որոնք համապատասխանում են նշված նմուշին։ 
Տվյալների բազայի միգրացիա (Database Migration) 
Տվյալների բազայի միգրացիան գործընթաց է, որի ընթացքում տվյալները 
տեղափոխվում են սկզբնաղբյուր տվյալների բազայից դեպի նպատակային 
տվյալների բազա։ Այն կարող է ներառել տարբեր DBMS-ների միջև տեղափոխում 
կամ նույն համակարգի նոր տարբերակի անցում։ Միգրացիան կիրառվում է 
համակարգերի արդիականացման, արտադրողականության բարձրացման և 
ամպային լուծումների անցման նպատակներով։

View, Stored Procedure և Trigger 
Տվյալների հենքերում հաճախ օգտագործվում են լրացուցիչ մեխանիզմներ, 
որոնք օգնում են ավելի արդյունավետ աշխատել տվյալների հետ։ 
View-ը վիրտուալ աղյուսակ է, որը ստեղծվում է SELECT հարցման հիման վրա։ Այն

Stored Procedure-ը SQL հրամանների հավաքածու է, որը պահվում է տվյալների

համար։ 
Trigger-ը հատուկ մեխանիզմ է, որը ավտոմատ կերպով ակտիվանում է, երբ 
տվյալների հենքում կատարվում են որոշակի գործողություններ, օրինակ՝ տվյալների 
ավելացում կամ փոփոխում։ 
Այս մեխանիզմները մեծապես հեշտացնում են տվյալների կառավարման

Տրիգերներ 
Տրիգերներն իրենցից ներկայացնում են նախապես որոշված գործողություն 
կամ գործողությունների հաջորդականություն, որն ավտոմատ կերպով կատարվում 
է, տվյալների նորացման, ավելացման կամ հեռացման գործողությունների 
կատարման ժամանակ: Ոչ օգտվողը, ոչ էլ ծրագրային հավելվածը չեն կարող 
ակտիվացնել տրիգերը, այն կատարվում է ավտոմատ կերպով, երբ օգտվողը կամ 
ծրագրային հավելվածը տվյալների բազայի կետ կատարում են որոշակի 
գործողություն: Տրիգերը պահվող պրոցեդուրայի հատուկ տեսակ է: Տրիգերներն 
ապահովում են տվյաների բազայի ցանկացած փոփոխության ճշտություն, նախքան 
այդ փոփոխությունների ընդունումը: 
Յուրաքանչյուր տրիգեր կցվում է որոշակի (կոնկրետ) աղյուսակի: Նրա կողմից

Authentication and Authorization Using Auth0 
Auth0-ն նույնականացման և հասանելիության կառավարման (Identity and 
Access Management — IAM) հարթակ է, որը նախատեսված է վեբ և ծրագրային 
համակարգերում օգտատերերի անվտանգ նույնականացման և թույլտվությունների 
կառավարման գործընթացը պարզեցնելու համար։ Այն տրամադրում է պատրաստի 
authentication և authorization մեխանիզմներ՝ հնարավորություն տալով 
ծրագրավորողներին խուսափել նույնականացման ամբողջ համակարգը զրոյից 
մշակելու անհրաժեշտությունից։ 
Auth0-ը հիմնված է ժամանակակից անվտանգության ստանդարտների վրա, որոնցից 
հիմնականը OAuth 2.0 արձանագրությունն է։ OAuth 2.0-ը թույլ է տալիս ապահով և 
վերահսկվող մուտք տրամադրել օգտատերերին՝ առանց գաղտնաբառերի 
անմիջական պահպանման ծրագրի կողմից։ Օգտատերը մուտքագրում է իր 
տվյալները Auth0-ի միջավայրում, իսկ համակարգը ստուգում է դրանց ճշտությունը և 
վերադարձնում է հաստատման արդյունքը։ Այս մոտեցումը բարձրացնում է 
համակարգի անվտանգությունը, քանի որ ծրագրի backend հատվածը չի պահպանում 
կամ մշակում օգտատերերի գաղտնաբառերը։ 
Տվյալների նորմալացում 
Տվյալների նորմալացումը տվյալների հենքի նախագծման կարևոր գործընթաց 
է, որի նպատակն է նվազեցնել տվյալների կրկնությունը և ապահովել տվյալների 
կառուցվածքային կազմակերպումը։ 
Նորմալացման ընթացքում տվյալները բաժանվում են տարբեր աղյուսակների 
այնպես, որպեսզի յուրաքանչյուր աղյուսակ պահպանի միայն անհրաժեշտ 
տվյալները։ 
Նորմալացման հիմնական մակարդակներն են․ 
Առաջին նորմալ ձև (1NF) – աղյուսակում չպետք է լինեն կրկնվող դաշտեր կամ 
բազմարժեք տվյալներ։ 
Երկրորդ նորմալ ձև (2NF) – յուրաքանչյուր ոչ բանալի դաշտ պետք է ամբողջությամբ 
կախված լինի առաջնային բանալուց։ 
Երրորդ նորմալ ձև (3NF) – աղյուսակում չպետք է լինեն ոչ ուղիղ կախվածություններ 
ոչ բանալի դաշտերի միջև։ 
Նորմալացման կիրառումը թույլ է տալիս ստեղծել արդյունավետ և ճիշտ 
կառուցվածքային տվյալների հենք։

  async getPatients({ limit, offset, search } = {}) { 
        const params = new URLSearchParams(); 
        if (limit  !== undefined) params.append("limit",  limit); 
        if (offset !== undefined) params.append("offset", offset); 
        if (search && search.trim() !== "") params.append("search", search.trim()); 
 
        const query = params.toString() ? `?${params.toString()}` : ""; 
        const response = await fetch(`${BASE_URL}/api/patients${query}`, { 
            headers: this.getHeaders(), 
        }); 
        if (!response.ok) return { success: false, status: response.status }; 
        const data = await response.json(); 
        // backend returns { patients: [...], total: N } 
        return { success: true, data }; 
    }

Եզրակացություն 
Սույն կուրսային աշխատանքի շրջանակներում նախագծվել և մշակվել է 
բուժհաստատության բժիշկների պորտալի տվյալների հենքը՝ «Portal for Doctors» 
համակարգը։ Աշխատանքի ընթացքում ուսումնասիրվել են տվյալների հենքերի 
նախագծման հիմնական սկզբունքները, հարաբերական տվյալների հենքի 
կառուցվածքային տարրերը, ինչպես նաև Microsoft SQL Server և PostgreSQL 
կառավարման համակարգերի հիմնական հնարավորությունները։ 
 
Նախագծված համակարգը ապահովում է բժիշկների արդյունավետ աշխատանքը՝ 
թույլ տալով պահել և կառավարել հիվանդների անձնական տվյալները, բժշկական 
այցելությունները, ախտորոշումները, հետազոտությունների արդյունքները և 
դեղորայքային նշանակումները։ Տվյալների հենքի կառուցվածքը ներառում է ‘‘doctors, 
patients, reports, notes, finances, notifications’’ և այլ աղյուսակներ, որոնք 
փոխկապակցված են առաջնային և արտաքին բանալիների միջոցով։ 
 
Տվյալների ամբողջականությունն ու անվտանգությունն ապահովվում են “Trigger”-
ների, “Stored Procedure”-ների և “View”-ների կիրառման միջոցով։ Կատարվել է նաև 
տվյալների նորմալացում՝ 1NF, 2NF, 3NF մակարդակների պահանջներին 
համապատասխան, ինչը նպաստել է տվյալների կրկնության վերացմանը և 
համակարգի արդյունավետության բարձրացմանը։
